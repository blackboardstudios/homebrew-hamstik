<h1 align="center">homebrew-hamstik</h1>

<p align="center">
  Official Homebrew tap for
  <a href="https://github.com/blackboardstudios/hamstik-cli">Hamstik CLI</a> —
  the native command-line interface for
  <a href="https://hamstik.com">Hamstik</a>.
</p>

This repository carries the `hamstik` formula so macOS and Linux users can
install the official Hamstik CLI with Homebrew. Formulas are generated
automatically from each stable release of
[blackboardstudios/hamstik-cli](https://github.com/blackboardstudios/hamstik-cli)
and committed here; every archive URL is pinned to a release tag with a
sha256 checksum.

> **Status:** Pre-alpha. The CLI's Public API v1 command surface is
> implemented, but the first supported release is still under development.
> Expect fast iteration.

[![License: Apache-2.0](https://img.shields.io/badge/license-Apache--2.0-blue.svg)](https://github.com/blackboardstudios/hamstik-cli/blob/main/LICENSE)

## Quick start

```bash
brew tap blackboardstudios/hamstik https://github.com/blackboardstudios/homebrew-hamstik
brew install blackboardstudios/hamstik/hamstik
hamstik --version
```

Because the tap lives at `blackboardstudios/homebrew-hamstik`, Homebrew can
also resolve the install without an explicit `brew tap` step:

```bash
brew install blackboardstudios/hamstik/hamstik
```

Verify the installation and its exact build identity:

```bash
hamstik version
# 🐹 hamstik cli v0.1.2      © Blackboard Studios LLC
#
# commit    <full sha of the release build>
# target    aarch64-apple-darwin
```

## First steps

The Personal Access Token is stored in the OS credential store (macOS
Keychain, or the Linux Secret Service) — never in plaintext:

```bash
hamstik auth login --with-token      # reads the PAT from stdin
hamstik context init --org acme --project HAM
hamstik work list --mine
```

For the full command surface — work items, sprints, labels, bulk operations,
search, dry-run previews, and the `gh api`-style passthrough — see the
[Hamstik CLI README](https://github.com/blackboardstudios/hamstik-cli#readme)
and the generated command reference in
[`docs/reference/`](https://github.com/blackboardstudios/hamstik-cli/tree/main/docs/reference).

## Supported platforms

The formula installs the prebuilt release binary — no Rust toolchain or other
runtime is required:

| Platform | Target triple |
| --- | --- |
| macOS — Apple Silicon | `aarch64-apple-darwin` |
| macOS — Intel | `x86_64-apple-darwin` |
| Linux — x86_64 | `x86_64-unknown-linux-gnu` |
| Linux — ARM64 | `aarch64-unknown-linux-gnu` |

Windows is not served by Homebrew; use the PowerShell installer, the
`winget` manifests, or the direct archives instead — every channel is
documented in [design/INSTALL.md](https://github.com/blackboardstudios/hamstik-cli/blob/main/design/INSTALL.md).

## What this tap contains

- `Formula/hamstik.rb` — the `hamstik` formula, generated by the CLI
  release pipeline (cargo-dist) and committed per stable release by the
  `publish-homebrew-formula` job.
- Nothing else: no bottles, no custom binaries. The formula downloads the
  same archives published on the
  [hamstik-cli releases page](https://github.com/blackboardstudios/hamstik-cli/releases)
  and verifies them against the release's sha256 checksums.

### How updates are published

- Each stable release of `hamstik-cli` regenerates the formula with the new
  version, archive URLs, and sha256 values, then commits it here
  automatically.
- Homebrew therefore sees an update only when a stable release is published;
  pre-releases (for example `0.1.1-rc.1`) do not touch this tap.
- The CLI has **no silent self-update and no telemetry** (by design — see
  SPEC §73 in the CLI repository). Updates happen only through Homebrew, on
  your command:

```bash
brew update && brew upgrade blackboardstudios/hamstik/hamstik
```

### Formula maintenance

The formula is machine-generated on every release. Manual edits are
overwritten by the next release run, so fixes that must persist (for
example `desc`, `homepage`, or install logic) belong in the CLI
repository's release configuration, not in this tap.

## Uninstalling

```bash
brew uninstall blackboardstudios/hamstik/hamstik
brew untap blackboardstudios/hamstik   # optional
```

Uninstalling never touches credentials: the OS keyring entry stays until
`hamstik auth logout` (run it first for a clean machine) or manual removal
from the keychain/Secret Service.

## Rolling back to a known-good version

Prior versions remain downloadable from the release list. To pin an older
release, extract the historical formula into a local tap:

```bash
brew tap-new <your-github-user>/local
brew extract --version=0.1.1 hamstik <your-github-user>/local
brew install <your-github-user>/local/hamstik@0.1.1
```

Or simply keep the previous release archive's binary alongside the new one
until the regression is resolved. `hamstik version` must report the
rolled-back version — that check is the rollback's acceptance test.

## Verifying a download

Every CLI release ships per-file sha256 checksums, an aggregate
`sha256.sum`, CycloneDX SBOMs, and Sigstore build-provenance attestations.
Before running a downloaded archive directly (outside Homebrew), verify it:

```bash
# Integrity: checksums (run inside the folder of downloaded files)
sha256sum -c sha256.sum

# Authenticity: provenance (requires the GitHub CLI, gh >= 2.57)
gh attestation verify hamstik-cli-aarch64-apple-darwin.tar.gz \
  --repo blackboardstudios/hamstik-cli

# Identity: the binary reports its exact build
./hamstik-cli-aarch64-apple-darwin/hamstik version
```

A download is trustworthy when all three hold. The release pipeline runs the
same checks before publishing. Full details, including the threat model:
[design/SIGNING.md](https://github.com/blackboardstudios/hamstik-cli/blob/main/design/SIGNING.md).

## Troubleshooting

```bash
hamstik doctor          # dependency-aware diagnostics, offline-safe with --local-only
brew info blackboardstudios/hamstik/hamstik
brew reinstall blackboardstudios/hamstik/hamstik
```

- **Stale formula:** run `brew update` first; Homebrew refreshes taps only
  on demand.
- **No secure credential store on Linux:** the CLI never falls back to
  plaintext storage. Set up a Secret Service (GNOME Keyring / KWallet), or
  use the ephemeral `HAMSTIK_TOKEN` environment variable for headless
  automation — it is never read from or written to the credential store.
- **Headless / CI usage:**

```bash
printf '%s\n' "$HAMSTIK_PAT" | hamstik --no-input auth login --with-token
hamstik --no-input --json auth status
```

- Anything that is not a formula/packaging problem belongs in the
  [hamstik-cli issue tracker](https://github.com/blackboardstudios/hamstik-cli/issues).
